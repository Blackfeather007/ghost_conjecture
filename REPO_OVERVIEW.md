# Repository Overview: `ghost_conjecture`

This repository is a Lean 4 project scaffolded around a “ghost conjecture” formalization, plus tooling to:

- keep a Lean Blueprint (PDF + web) and publish it via GitHub Pages,
- extract theorem/definition/etc. blocks from arXiv LaTeX into JSON,
- edit/annotate dependency information in a small web UI,
- (optionally) convert that JSON back into blueprint-style LaTeX snippets.

Per request, the contents of `data/*.tex` were **not** read; only filenames are listed.

## Top-level layout

```
.
├─ GhostConjecture/              # Lean source files (Lean library)
├─ blueprint/                    # Lean Blueprint sources (LaTeX + config)
├─ data/                         # Input LaTeX sources (arXiv) + small example snippet
├─ home_page/                    # Jekyll site for GitHub Pages (hosts blueprint + docs)
├─ output/                       # Example extracted JSON output
├─ scripts/                      # Python tooling: extract -> JSON, JSON -> blueprint LaTeX
├─ ui/                           # Browser UI to inspect/edit extracted items & dependencies
├─ .github/workflows/            # GitHub Actions: CI, blueprint build, deploy, dependency updates
├─ GhostConjecture.lean          # Lean “umbrella” import file for the library
├─ lakefile.toml                 # Lake project config (deps, targets, options)
├─ lake-manifest.json            # Pinned dependency lockfile generated by Lake
├─ lean-toolchain                # Lean version pin (used by elan/lake)
└─ README.md                     # Minimal repository readme
```

## What each part is for

### Lean project (`GhostConjecture/`, `lakefile.toml`, `lean-toolchain`)

- `lean-toolchain` pins the Lean toolchain to `leanprover/lean4:v4.27.0`.
- `lakefile.toml` defines the project `ghost_conjecture` and pulls in:
  - `mathlib` (tag `v4.27.0`),
  - `checkdecls` (used to verify blueprint-referenced declarations exist),
  - `doc-gen4` (for API documentation generation).
- `GhostConjecture.lean` imports `GhostConjecture.Basic`.
- `GhostConjecture/Basic.lean` currently contains a placeholder `def hello := "world"`.

### Blueprint (`blueprint/`)

This is a standard Lean Blueprint LaTeX skeleton intended to be built by `leanblueprint` into:

- a printable PDF (`blueprint/print/print.pdf`, copied to `home_page/blueprint.pdf` by CI),
- a web version (`blueprint/web/`, copied to `home_page/blueprint/` by CI).

Key files:

- `blueprint/src/content.tex`: where the blueprint’s mathematical narrative would go (currently a template comment).
- `blueprint/src/print.tex`, `blueprint/src/web.tex`: the LaTeX entry points for PDF/web builds.
- `blueprint/src/macros/*.tex`: common + web/print-specific macro hooks.
- `blueprint/src/plastex.cfg`, `blueprint/src/latexmkrc`: configuration for web rendering (plasTeX) and PDF builds.

### Data and outputs (`data/`, `output/`)

- `data/` holds LaTeX sources (arXiv papers) that can be used as inputs to the extraction scripts:
  - `data/arXiv-2206.15372v2.tex`
  - `data/arXiv-2206.15372v2_expanded.tex`
  - `data/arXiv-2302.07697v2.tex`
  - `data/arXiv-2302.07697v2_expanded.tex`
- `data/leanblueprint.example` is a small example of blueprint-style theorem/proof markup with `\lean{...}` and `\uses{...}`.
- `output/arXiv-2206.15372v2.json` is an example JSON file containing extracted items (type/label/content/section/proof/dependencies).

### Python scripts (`scripts/`)

- `scripts/extract_math_content.py`: reads a `.tex` file and extracts environments such as `definition`, `theorem`, `lemma`, etc.; it also looks for an immediately-following `proof` environment and extracts `\ref{...}` / `\eqref{...}` dependencies.
  - Note: the script is currently written to look for input under `scripts/data/` and write to `scripts/output/` (paths are relative to the script location), while this repository stores inputs in `data/` and outputs in `output/`.
- `scripts/json_to_latex.py`: converts the extracted JSON format into Lean Blueprint-style LaTeX blocks, adding `\lean{...}`, `\leanok`, and `\uses{...}`.

### Web UI (`ui/`)

A standalone browser UI for working with extracted JSON files:

- `ui/index.html`: the page layout; loads KaTeX (math rendering) and `vis-network` (dependency graph) from CDNs.
- `ui/app.js`: JSON loading, filtering/search, editing, dependency management, and optional graph view.
- `ui/styles.css`: UI styling.
- `ui/README.md`: usage instructions and data format notes.

### GitHub Pages site (`home_page/`)

A Jekyll site that CI can populate with:

- the blueprint web output (`home_page/blueprint/`) and PDF (`home_page/blueprint.pdf`),
- generated API docs (`home_page/docs/`).

Key files:

- `home_page/index.md`: links to blueprint and documentation.
- `home_page/_layouts/default.html`: site layout with buttons to blueprint/docs.
- `home_page/_config.yml`, `home_page/Gemfile`, `home_page/Gemfile.lock`: Jekyll/GitHub Pages configuration.

### CI / automation (`.github/workflows/`)

- `blueprint.yml`: builds the Lean project, caches doc builds, builds API docs + blueprint (PDF + web), runs `checkdecls`, builds the Jekyll site (if `home_page/` exists), and deploys to GitHub Pages.
- `lean_action_ci.yml`: basic CI using `lean-action` + `docgen-action`.
- `update.yml`: runs `mathlib-update-action` (manual trigger enabled) to open PRs/issues for dependency bumps.
- `create-release.yml`: tags/releases on changes to `lean-toolchain`.

## Quick entry points

- Lean build: `lake build`
- Blueprint build (requires `leanblueprint`): `leanblueprint pdf` and `leanblueprint web`
- UI: open `ui/index.html` (or run `python3 -m http.server` inside `ui/`)
